# Belshazaar

Belshazaar is a command-line tool for analyzing Azure Role-Based Access Control (RBAC) actions to detect overly broad wildcard permissions.  
It expands wildcards using a formal grammar over Azure's action catalog.

The tool works in two modes:
- **single run**
- **batch**

---

## Key Capabilities

- **Single Action Analysis** — Expand any single wildcard action and analyze its matching set.
- **Batch Wildcard Discovery** — Generate wildcards and their extreme action pairs based on Azure’s official action list.
- **Batch Customer Policy Evaluation** — Analyze your custom wildcards against Azure’s action catalog.
- **NotActions Support** — Analyze wildcard coverage considering exclusions via NotActions.

---

## Data Preparation

Before running the tool, first extract the up-to-date actions list from Microsoft:

```
./extractAzureActions.sh
```

This will generate a file called azureActions.txt containing all current Microsoft Resource Provider actions

Note that third party Resource Providers (like Oracle) won't be listed here.

# Batch modes
Belshazaar works with official Azure action catalogs and customer policy extracts.

## Understanding distances and wildcard reach
In batch modes, Belshazaar will provide a numerical value called the distance (or the reach) of wildcard actions. 

The distance ranges from 1 to 8. To achieve least privileges, we want to ***maximize*** the reach as much as possible.

A distance of 1 corresponds to a cross Resource Provider reach: put it another way, the wildcards allows lateral motion from Microsoft.ApiCenter to Microsoft.ApiManagement for instance.

A distance of 2 corresponds to a lateral motion within the top level domain of a resource provider. It allows lateral motion from Microsft.AAD/domainServices to Microsoft.AAD/Operations for instance.

A distance of 8 corresponds to a smallest possible lateral motion in the hierarchy of Azure Resource Providers, from Microsoft.Sql/managedInstances/databases/schemas/tables/columns/sensitivityLabels/disable/action to Microsoft/Sql/managedInstances/databases/schemas/tables/columns/sensitivityLabels/enable/action for instance.

## Azure Wildcards Discovery

To discover very permissive (i.e. low distance) wildcards in the catalog of Azure actions, run

```
./belshazaar.py --discover
```

The script will produce a CSV file 
```
widcard;diameter;left_pair;right_pair

Microsoft.AAD/*ns/read;2;Microsoft/AAD/Operations/read;Microsoft/AAD/domainServices/providers/Microsoft/Insights/logDefinitions/read
```

The first string, ***Microsoft.AAD/*ns/read***, is a wildcard action generated by Belshazaar. The minimum reach of this wildcard is indicated by the ***diameter***, which is 2 in this example. 
The last two strings are a pair of actions which act as witnesses for the diameter: the left and right legs represent two actions standing 2 levels apart in Azure's Resource Providers hierarchy. 


Warning! The discover mode takes a long time to run, typically several hours.

## Customer Wildcards Evaluation

Belshazaar may also analyze all the wildcards in the actions of your Azure Role assignements, calculate their reach and propose sample pairs justifying the reach. 

You must first run silhouette, then

```
./extractCustomerWildcardActions.sh
```

This will generate a file called customerWildcardActions.txt

To evaluate your customer wildcards, run

```
./belshazaar.py --evaluate
```

This will generate a CSV file using the exact same format as the discover option.
